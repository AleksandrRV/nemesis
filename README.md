# Nemesis Digital

Неофициальная цифровая адаптация настольной игры **Nemesis** (автор Адам Квапинский, издатель Awaken Realms, 2018): партия в браузере. Правила готовят стол на 1–5 игроков; интерфейс пока ведёт одного персонажа — офлайн-соло без сети.

> **Это фанатский проект для личного использования.** Он не связан с правообладателями, не одобрен ими и не предназначен для коммерческого использования. Проект переносит оригинальную игру 1:1 и работает только с оригиналами — книгой правил, картами и артом; правовые вопросы в нём не рассматриваются (см. [NOTICE](NOTICE.md)).

Проект написан на TypeScript как два пакета: правила живут в общем ядре, а интерфейс общается с ним только действиями игрока и получает **отфильтрованное** состояние — то, что персонаж действительно может знать.

**Текущая версия: 0.1.11** — её же показывает HUD приложения: строка версии живёт в `package.json` и подставляется сборкой, а не правится в двух местах. История изменений — в [CHANGELOG](CHANGELOG.md), разбор ревизии 0.1.9 — в [doc/review-0.1.9.md](doc/review-0.1.9.md), план исправлений — в [doc/fix-plan-0.1.9.md](doc/fix-plan-0.1.9.md).

## Что уже работает

- **Карта корабля**: 21 отсек и 29 коридоров, жетоны Дверей (открыта / закрыта / разрушена). Разрушенная Дверь терминальна — снова её не закрыть (стр. 17), жетонов Дверей 12, и при пустом запасе жетон переставляется с поля.
- **Подготовка партии на 1–5 игроков**: мешок Чужих (3 взрослых плюс по одному за каждого игрока), инверсная пара жетонов двигателей, Спасательные Капсулы по числу игроков (2–4), случайная карта Координат, жетоны Исследования по отсекам, шесть пресетов персонажей. Один и тот же сид всегда даёт одну и ту же партию: случайность разведена по потокам (расклад, Шум, мешок, колоды, бои), поэтому посторонний бросок не сдвигает расклад. Сид показан в HUD и копируется по нажатию.
- **Движок правил**: перемещение только в соседний отсек через связь и открытую Дверь; «Осторожное движение» кладёт маркер Шума в выбранный Коридор вместо броска; запас маркеров честный — 30 Шума, 8 Пожара, 8 Неисправности, — и когда запаса Пожара или Неисправности больше нет, корабль взрывается или обшивка не выдерживает: партия заканчивается, а не «дорисовывает» маркер; вскрытие неисследованного отсека разыгрывает эффект жетона Исследования (Пожар, Неисправность, Слизь, Двери, Тишина, Опасность), после чего бросается кубик Шума с гранями 1, 1, 2, 2, 3, 3, 4, 4, Тишина, Опасность; маркер Шума встаёт в Коридор с выпавшим номером (включая Технические Коридоры), «Опасность» помечает все пустые Коридоры отсека, а Контакт — то, что пока не реализовано, — отклоняется явной ошибкой, а не разыгрывается наугад. Отладочные переключатели дверей и шума доступны только под флагом dev-сборки.
- **Журнал действий**: в нижней части игрового экрана открыта чёрная сворачиваемая панель. Она показывает перемещения с Коридорами, вскрытие отсеков, жетоны Исследования и их эффекты, результаты и маркеры Шума, пропуски Шума, dev-изменения и окончание партии. События типизированы, имеют последовательные идентификаторы, сохраняются в партии и форматируются с контрастными цветами и жирными ключевыми сущностями; подробности — в [doc/game-log.md](doc/game-log.md).
- **Честность среза**: двигатели и Координаты скрыты до личной проверки, невскрытый тайл не раскрывает ни название, ни жетон Исследования (включая его эффект), ни компьютер, ни аварии; порядок мешка Чужих заменён составом по типам, порядок добора личных колод не видит даже владелец, чужая рука скрыта, инвентарь, квестовые предметы и цели другого персонажа скрыты, карты Заражения — до проверки сканером, Слабости лежат рубашкой вверх.
- **Офлайн-соло**: партия сохраняется в браузере и продолжается после перезапуска, сеть для игры не требуется. Партия стартует и по `http://` с LAN-адреса (с телефона в той же Wi-Fi): сид не зависит от `crypto.randomUUID`, которого в небезопасном контексте нет. Отказ движка показывается игроку причиной, а не падением интерфейса.

## Быстрый старт

```bash
npm ci        # установка зависимостей воркспейсов по lock-файлу
npm run dev   # dev-сервер Vite: http://localhost:5173
```

Требования: Node.js 20+ (проверено на 22.22.3) и npm 10+.

В dev-сборке в HUD есть кнопка **dev-панели**: диагностика партии (сид, режим, срез отфильтрованного состояния), старт с заданным сидом и отладочные переключатели Дверей и Шума. В игровом интерфейсе читерских элементов нет, в продакшн-сборку панель не попадает, а отладочные действия движок в любом случае отклоняет вне dev-режима.

## Команды

| Команда                               | Что делает                                                       |
| ------------------------------------- | ---------------------------------------------------------------- |
| `npm run dev`                         | dev-сервер клиента с горячей перезагрузкой                       |
| `npm run build`                       | сборка ядра и клиента в `packages/*/dist`                        |
| `npm run verify`                      | тип-чек, ESLint, Prettier и тесты — одна проверка перед коммитом |
| `npm test`                            | тесты (vitest, проекты `shared` и `client`)                      |
| `npm run test:coverage`               | тесты с покрытием                                                |
| `npm run lint:fix` / `npm run format` | автоисправления линтера и форматирования                         |

## Структура

| Путь              | Что там                                                                                                                                       |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/shared` | ядро: контракт `GameState`, данные (граф корабля, отсеки, рецепты, пресеты), движок правил и фильтр скрытой информации. Без DOM, React и сети |
| `packages/client` | интерфейс на React, нижний журнал действий, транспорт (`IGameTransport`), офлайн-партия и сохранение, стор                                    |
| `doc/`            | аудит, GDD, техстек, дорожная карта                                                                                                           |
| `AGENTS.md`       | регламент работы агентов и разработчиков в этом репозитории                                                                                   |

Как всё связано: клиент не меняет состояние партии сам — он отправляет действие через транспорт, движок ядра проверяет его по правилам, а наружу возвращается только представление игрока (`filterStateForPlayer`). Поэтому правила нельзя «обойти» через интерфейс, а скрытые данные не попадают в UI.

## Ограничения

- **Состава колод в репозитории нет.** Карты предметов, события, травмы, цели и Слабости описаны структурой, но не наполнены данными: их перечни — охраняемые материалы, и в проект они попадут только в виде собственных таблиц проекта. Пока не реализованы поиск, создание предметов, бой и цели.
- **Пул Чужих, Контакт и бой — этап 4 дорожной карты.** Мешок Чужих тасуется и его состав виден в срезе, но вытягивание жетонов и Внезапная атака ещё не разыгрываются: если маркер Шума должен лечь в Коридор, где уже есть маркер (это и есть Контакт), действие отклоняется явной ошибкой.
- **Данные поля ещё сверяются с физическими компонентами.** Пул жетонов Исследования (20 жетонов, 44 предмета) и жетоны Чужих пришли из внешних переписей компонентов и подтверждений владельца проекта, но не из фото в репозитории; топология Коридоров и номера выходов читаются только с поля и не сверялись, поэтому парные Коридоры пока описаны одной связью. Все эти места помечены в [`doc/sources/data-sources.json`](doc/sources/data-sources.json) статусами `EXTERNAL_UNVERIFIED` и `UNVERIFIED_BOARD` со списком `unverified`; пока сверки нет, бросок Шума на номер, которого нет среди выходов отсека, разыгрывается как «Тишина».
- **Интерфейс ведёт одного персонажа.** Стол готовится на 1–5 игроков, но сетевой партии и смены активного игрока в UI ещё нет (этапы 10–11 дорожной карты).
- Реализованные механики соответствуют книге правил; номера страниц в комментариях («стр. 14») — это ссылки-ориентиры.

## Правила игры и источники

Единственный источник истины по механике — **оригинальная книга правил**, её текст лежит в репозитории: [`doc/rules.md`](doc/rules.md). К нему относятся все ссылки «стр. N» в коде и документации.

Проект переносит игру **1:1**: механики, порядок фаз, стоимости действий, структура колод, названия карт, отсеков и символов берутся из оригинала без упрощений и «балансировок»; отклонение от оригинала считается дефектом. Источники — только оригиналы: книга правил, оригинальные карты и оригинальный арт (без фанатских пересказов и самодельных подмен).

Утверждение «1:1» проверяемое, а не декларативное: у каждой таблицы данных есть запись в пакете источника [`doc/sources/data-sources.json`](doc/sources/data-sources.json) — откуда взято каждое число (строки `doc/rules.md`, подтверждение владельца компонентов, внешний источник), — а golden-тесты [`sources.golden.test.ts`](packages/shared/src/data/sources.golden.test.ts) сверяют код с этим файлом. Что ещё не сверено с физическими компонентами, помечено в пакете статусами `USER_CONFIRMED`, `EXTERNAL_UNVERIFIED` и `UNVERIFIED_BOARD` и перечислено в списке `unverified`: пока такой пометки нет, непроверенное не выдаётся за проверенное.

Правовые аспекты в проекте не рассматриваются: это некоммерческий фанатский проект для личного использования, юридическая экспертиза не проводилась и не планируется, а агентам и разработчикам запрещено заниматься правовыми вопросами вместо реализации игры. Подробнее — в [NOTICE](NOTICE.md).

## Качество

Перед коммитом проект проверяется целиком:

```bash
npm run verify   # типы + линтер + формат + тесты
```

На версии 0.1.11: 327 тестов в 23 файлах. Покрытие `packages/shared`: 100 % строк в данных, контрактах и утилитах и 97 % в движке правил (ветви ниже — часть из них защиты от недостижимых состояний); клиентские сервисы, стор, сохранение, модель dev-панели и модель журнала — покрыты тестами, React-компоненты (карта, инспектор, HUD и панель журнала) юнит-тестами пока не покрыты. Подробности — в отчёте `npm run test:coverage`. Тесты лежат рядом с кодом (`*.test.ts`): инварианты графа и подготовки партии, журнал событий, правила движка (включая вскрытие отсека и кубик Шума), фильтр скрытой информации, сохранение и транспорт.

Каждый push и pull request прогоняет те же проверки в CI (`.github/workflows/ci.yml`): `npm ci`, `npm run verify`, продакшн-сборка и отдельный шаг, который падает, если в бандл попали строки отладочной панели.

Проект некоммерческий и фанатский: код предоставляется «как есть» для личного и образовательного использования, права на игру остаются у правообладателей. Статус проекта, источники и правило «1:1» — в [NOTICE](NOTICE.md).
