# Nemesis Digital

Неофициальная цифровая адаптация настольной игры **Nemesis** (автор Адам Квапинский, издатель Awaken Realms, 2018): партия в браузере для 1–5 игроков, включая офлайн-соло без сети.

> **Это фанатский проект.** Он не связан с правообладателями, не одобрен ими и не предназначен для коммерческого использования. Права на игру, её название, правила и материалы принадлежат их владельцам — см. [NOTICE](NOTICE).

Проект написан на TypeScript как два пакета: правила живут в общем ядре, а интерфейс общается с ним только действиями игрока и получает **отфильтрованное** состояние — то, что персонаж действительно может знать.

**Текущая версия: 0.1.7** (её же показывает HUD приложения). Актуальный статус пунктов аудита и версия — в [doc/audit-0.1.0.md](doc/audit-0.1.0.md).

## Что уже работает

- **Карта корабля**: 21 отсек и 29 коридоров, жетоны Дверей (открыта / закрыта / разрушена).
- **Подготовка партии на 1–5 игроков**: мешок Чужих (3 взрослых плюс по одному за каждого игрока), инверсная пара жетонов двигателей, Спасательные Капсулы по числу игроков (2–4), случайная карта Координат, жетоны Исследования по отсекам, шесть пресетов персонажей. Один и тот же сид всегда даёт одну и ту же партию.
- **Движок правил**: перемещение только в соседний отсек через связь и открытую Дверь, вскрытие неисследованного отсека через стек прерываний, отладочные переключатели дверей и шума — под флагом dev-сборки. Действие, которое ещё не реализовано, отклоняется явной ошибкой, а не «ничем».
- **Фильтр скрытой информации**: двигатели и Координаты скрыты до личной проверки, невскрытый тайл не раскрывает ни название, ни жетон Исследования, ни компьютер, ни аварии, чужие инвентарь, квестовые предметы и цели скрыты, карты Заражения — до проверки сканером, Слабости лежат рубашкой вверх.
- **Офлайн-соло**: партия сохраняется в браузере и продолжается после перезапуска, сеть не требуется. Отказ движка показывается игроку причиной, а не падением интерфейса.

## Быстрый старт

```bash
npm ci        # установка зависимостей воркспейсов по lock-файлу
npm run dev   # dev-сервер Vite: http://localhost:5173
```

Требования: Node.js 20+ (проверено на 22.22.3) и npm 10+.

В dev-сборке в HUD есть кнопка **dev-панели**: диагностика партии (сид, режим, срез отфильтрованного состояния), старт с заданным сидом и отладочные переключатели Дверей и Шума. В игровом интерфейсе читерских элементов нет, в продакшн-сборку панель не попадает, а отладочные действия движок в любом случае отклоняет вне dev-режима.

## Команды

| Команда                               | Что делает                                                       |
| ------------------------------------- | ---------------------------------------------------------------- |
| `npm run dev`                         | dev-сервер клиента с горячей перезагрузкой                       |
| `npm run build`                       | сборка ядра и клиента в `packages/*/dist`                        |
| `npm run verify`                      | тип-чек, ESLint, Prettier и тесты — одна проверка перед коммитом |
| `npm test`                            | тесты (vitest, проекты `shared` и `client`)                      |
| `npm run test:coverage`               | тесты с покрытием                                                |
| `npm run lint:fix` / `npm run format` | автоисправления линтера и форматирования                         |

## Структура

| Путь              | Что там                                                                                                                                       |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/shared` | ядро: контракт `GameState`, данные (граф корабля, отсеки, рецепты, пресеты), движок правил и фильтр скрытой информации. Без DOM, React и сети |
| `packages/client` | интерфейс на React, транспорт (`IGameTransport`), офлайн-партия и сохранение, стор                                                            |
| `doc/`            | аудит, GDD, техстек, дорожная карта                                                                                                           |
| `AGENTS.md`       | регламент работы агентов и разработчиков в этом репозитории                                                                                   |

Как всё связано: клиент не меняет состояние партии сам — он отправляет действие через транспорт, движок ядра проверяет его по правилам, а наружу возвращается только представление игрока (`filterStateForPlayer`). Поэтому правила нельзя «обойти» через интерфейс, а скрытые данные не попадают в UI.

## Ограничения

- **Состава колод в репозитории нет.** Карты предметов, события, травмы, цели и Слабости описаны структурой, но не наполнены данными: их перечни — охраняемые материалы, и в проект они попадут только в виде собственных таблиц проекта. Пока не реализованы поиск, создание предметов, бой и цели.
- Реализованные механики соответствуют книге правил; номера страниц в комментариях («стр. 14») — это ссылки-ориентиры.

## Правила игры и материалы правообладателя

Текст книги правил, сканы, арт, тексты карт и другие материалы игры **в репозитории не публикуются** — они охраняются авторским правом (подробности в [NOTICE](NOTICE)).

Для разработки книга правил нужна локально: положите свою копию в `doc/rules.md`. Этот путь добавлен в `.gitignore`, в репозиторий он не попадёт, и именно к нему относятся ссылки «стр. N» в коде и документации.

## Качество

Перед коммитом проект проверяется целиком:

```bash
npm run verify   # типы + линтер + формат + тесты
```

На версии 0.1.7: 206 тестов в 14 файлах, покрытие ядра `packages/shared` — 100 %, покрытие клиентских сервисов и стора — в отчёте `npm run test:coverage`. Тесты лежат рядом с кодом (`*.test.ts`): инварианты графа и подготовки партии, правила движка, фильтр скрытой информации, сохранение и транспорт.
