# Этап 0.4.0 — Шаг 1: контракт боевых данных

Реализован в **0.2.12**, 21 сентября 2026 года. Это подготовка данных и RNG, не выпуск всего этапа 0.4.0.

## Границы

Включены типы, таблица 20 Атак Чужих, шесть граней кубика, детерминированная подготовка колоды, функция броска, публичные экспорты и проверки интеграции с сохранением/санитайзером.

Не включены Контакт, нанесение ран, применение эффектов карт, стойкость, отступление, классовые действия и новые UI. Их существующие явные отказы не заменены молчаливыми заглушками. Шаги 2–8 остаются отдельными задачами.

## Модель Чужого

Используется уже существующий `IntruderEntity` из `types/entities.ts`:

| Поле | Контракт |
| --- | --- |
| `id` | Идентификатор особи на поле; уникальность обеспечивает процедура размещения следующего шага |
| `type` | `LARVA`, `CREEPER`, `ADULT`, `BREEDER`, `QUEEN`; BLANK не является особью |
| `roomId` | Идентификатор комнаты из существующей модели корабля |
| `woundsCount` | Текущее число накопленных ран |

Поле `woundsCount` не переименовывается в `wounds`: существующие потребители, фикстуры и sanitized-контракт уже используют его. В новой партии особей на поле ещё нет.

## Колода Атак Чужих

`IntruderAttackCard` определён **в одном месте**, `types/cards.ts`, и используется в `GameDecksState` и `SanitizedDecksState`.

| Поле | Назначение |
| --- | --- |
| `id` | Стабильный цифровой ID каждого из 20 экземпляров, включая одинаковые карты |
| `name`, `description` | Название и текст эффекта |
| `effect` | Типизированный идентификатор: `SCRATCH`, `BITE`, `CLAW_ATTACK`, `TAIL_ATTACK`, `TRANSFORMATION`, `FRENZY`, `SLIME`, `CALL` |
| `toughness` | Напечатанная стойкость для проверки результата атаки персонажа |
| `hasRetreat` | Наличие стрелки Отступления |
| `attackerTypes` | Символы типов, которые могут совершить эту атаку; Личинка исключена типом `IntruderAttackerType` |

Данные находятся в `data/intruderAttacks.ts`. Функция `createInitialDecks` тасует новые независимые экземпляры через существующий генератор `cards`, после прежних колод. Их порядок для прежних сидов сохраняется. Начальный сброс Атак пуст. Копируются и карточные объекты, и вложенные массивы символов; изменение одной партии не затрагивает другую или шаблон.

Тексты «Укуса» и «Атаки хвостом» сохраняют указанное в транскрипте условие **немедленной смерти**, а не заменяют его дополнительными Травмами. Применение этого условия будет реализовано в обработчике атак, не в данном шаге. Машинный `effect` позволит обработчикам не зависеть от русского названия карты.

## Кубик и детерминизм

`data/combatDie.ts` задаёт шесть физических граней:

`MISS, MISS, TAIL, SILHOUETTES, ONE_WOUND, TWO_WOUNDS`.

Пять различных результатов не означают пятигранный кубик. Отдельная «Лапа» не вводится. Имена исходов соотнесены с обозначениями транскрипта в пакете источника.

`logic/combatDie.ts` экспортирует `rollCombatDie(state)`:

- берёт ровно одно значение существующего потока `combat` в позиции `meta.rngDraws.combat`;
- отображает его на одну из шести физических граней;
- увеличивает только `combat` на 1;
- не изменяет колоды, комнаты, мешок, раны и журнал;
- поддерживает Immer draft и продолжение после JSON-сохранения;
- отвергает недопустимую позицию через общий RNG, не изменяя состояние.

При подготовке партии `combat` остаётся в позиции 0: новая колода тасуется потоком `cards`. Новый генератор, глобальный счётчик, `Math.random()` или временные ID не вводятся.

## Происхождение данных

Пакет источника `doc/sources/data-sources.json` содержит отдельные таблицы `combat-die` и `intruder-attacks`.

Книга правил подтверждает d6, 20 карт, назначение полей, пять исходов кубика и атаку Личинки без карты. Конкретные частоты граней, распределение стойкости/стрелок/символов и тексты всех экземпляров взяты из предоставленного `doc/data/INTRUDERS.md`, разделы 1 и 4.

Для этих физических подробностей сохранён статус **`EXTERNAL_UNVERIFIED`** с перечнем несверенного. Заголовок «Verified» в транскрипте не является независимым подтверждением компонентов; выводить дублирование Промаха только из числа разных исходов нельзя. Оригинальные фотографии/сканы в рамках этой работы не сверялись.

Golden-проверки сравнивают не только размеры массивов: проверяется **каждая карта целиком**, включая ID, эффект, текст, стойкость, стрелку и символы, а также частоты семейств и точный список граней. Это защита от расхождения кода с зафиксированным источником, не доказательство достоверности самого транскрипта.

## Совместимость сохранений

`GAME_STATE_SCHEMA_VERSION` повышен с 4 до **5**: контракт карты изменился, в новой партии появилась обязательная заполненная колода Атак. Версия локальной сессии берётся из той же константы. Старые сохранения не дополняются молча придуманным порядком карт — штатный загрузчик их отвергает и создаёт новую партию.

Тесты проверяют реальный `serializeSession → parseSession`, сохранение порядка добора и публичного сброса, ненулевой счётчик и идентичность последующих бросков. Состояние v4 отвергается даже при попытке обернуть его в оболочку текущей версии.

## Публичная граница

`COMBAT_DIE_FACES`, `CombatDieFace`, `INTRUDER_ATTACK_CARDS`, типы карт и `rollCombatDie` доступны через `@nemesis/shared`. Дублирующих определений и глубинных клиентских импортов нет.

Существующий санитайзер не пришлось менять. Тестами зафиксировано: порядок и содержимое закрытой стопки Атак не выходят наружу; открытый сброс виден всем; перестановка закрытой колоды не меняет публичное состояние; клиентская копия не разделяет карточные объекты с ядром.
